# ShortcutKeyCounter Lunaサブエージェント実装計画

対象: `ShortcutKeyCounter.zip`  
目的: Lunaモデルでも安全に実装できる粒度まで完成作業を分解し、サブエージェントへ順番に割り当てる。

---

# 1. 基本方針

Lunaへ大きなPhaseをそのまま渡さない。

1タスクは原則として以下を満たすこと。

- 目的は1つだけ
- 変更対象は1〜3ファイル程度
- 既存仕様を変更しない
- 完了条件を自動テストまたは明確な手動確認で判定できる
- 他タスクの設計判断をしない
- 要求外のリファクタリングをしない
- 完了後に変更ファイルとテスト結果を報告する

---

# 2. 管理エージェントの役割

管理エージェントは大量の実装を担当せず、次を行う。

- タスクを順番にサブエージェントへ割り当てる
- 依存関係を管理する
- shared fileの変更を統合する
- 各タスクの成果をレビューする
- fmt / Clippy / testを実行する
- 競合を解消する
- タスク完了を記録する
- 問題があれば新しい修正タスクを発行する
- Wave Gateを通過した場合だけ次Waveへ進める

---

# 3. Shared Fileルール

以下は競合しやすいため、原則として管理エージェント所有とする。

```text
Cargo.toml
Cargo.lock

apps/shortcut-key-counter/Cargo.toml
apps/shortcut-key-counter/src/main.rs
apps/shortcut-key-counter/src/lib.rs

apps/shortcut-key-counter/src/app_state.rs       ※追加後
apps/shortcut-key-counter/src/tauri_commands.rs  ※追加後

apps/shortcut-key-counter/ui/src/api.ts           ※追加後
apps/shortcut-key-counter/ui/src/types.ts         ※追加後
apps/shortcut-key-counter/ui/src/main.ts          ※追加後
```

サブエージェントがShared File変更を必要とした場合は、直接変更せず、

```text
Integration Request:
- apps/shortcut-key-counter/src/lib.rs に `pub mod app_state;` が必要
```

のように完了報告へ記載する。

ただし管理エージェントが「このタスクでは変更可」と明示した場合だけ変更してよい。

---

# 4. Branch / Worktree方針

推奨:

```text
main
agent/m01-runtime-init
agent/m02-exclusion-shared
agent/m07-shortcut-ranking
...
```

原則:

```text
1タスク = 1 branch
```

または、小タスク2〜3個を1branchとしてもよい。

各タスク終了時に管理エージェントがreviewしてから統合する。

# Wave 1: Backend安定化

## M01 Runtime初期化二重実行修正

### 目的

`CaptureRuntime::start()` 内で `initialize()` が2回呼ばれている問題を解消する。

### 変更可

```text
apps/shortcut-key-counter/src/runtime.rs
apps/shortcut-key-counter/src/startup.rs
```

### 実装

現在:

```text
initialize()
↓
auto start sync
↓
initialize()
```

を、

```text
initialize()
↓
StartupContextを保持
↓
auto start sync
↓
同じStartupContextからruntime開始
```

へ変更する。

### 完了条件

- `initialize()` は起動1回につき1回
- `app_started` が二重記録されない
- retention cleanupが二重実行されない
- existing testsが通る

### 禁止

- Tauri導入
- UI変更
- DB schema変更
- Capture Worker設計変更

## M02 Shared Exclusion型の導入

### 目的

Capture Workerが起動後にも除外一覧変更を参照できる土台を作る。

### 変更可

```text
apps/shortcut-key-counter/src/capture_worker.rs
```

### 実装

現在:

```rust
HashSet<String>
```

をworker内部で固定保持している。

shared型を導入する。

例:

```rust
pub type SharedExcludedApps = Arc<RwLock<HashSet<String>>>;
```

`start_capture_worker()` がSharedExcludedAppsを受け取るようにする。

### 注意

`process_captured_input()` のunit testは可能な限り単純なHashSet利用を維持してよい。

run_worker側だけshared setからsnapshot/readする設計でもよい。

### 完了条件

- Worker起動後に除外setを書き換え可能
- raceなし
-既存の除外判定testが通る
- lock poisonをpanicにしない

### 禁止

DBから直接worker内で除外一覧を再読込しない。

