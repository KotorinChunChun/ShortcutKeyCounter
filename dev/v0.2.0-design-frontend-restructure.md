## 1. 背景

`ui/src/main.ts`は1,843行で、状態、画面遷移、描画、イベント結線が集中している。`package.json`がなくTypeScript版が固定されず、TSテストもない。

問題は行数そのものではなく、次の点である。

- 変更時に無関係な画面まで影響する。
- Tauri APIとDOMロジックが密結合し、単体テストできない。
- Node依存と生成手順が再現されない。
- `ui/dist`のコミットでソースと生成物の二重管理が発生する。

## 2. 目的

1. Node、TypeScript、Vite、Vitestをlockファイルで固定する。
2. Tauri API境界、状態、routing、純粋なformat処理を分離する。
3. 変更頻度と事故影響の高い画面から段階分割する。
4. CIとリリースで`ui/dist`を毎回生成し、Git管理を廃止する。

## 3. 採用構成

```text
ui/src/
  main.ts             起動のみ
  api.ts              Tauri invoke/listen境界
  app/
    state.ts          共有状態
    router.ts         画面遷移と未保存ガード入口
  shared/
    dom.ts
    format.ts
    theme.ts
    toast.ts
    modal.ts
  pages/
    key-mapping.ts
    settings.ts
    dashboard.ts
    ...               残りは変更時に段階移行
```

フレームワークは導入しない。モジュールの責務とテスト容易性を優先し、`main.ts 200行以下`や`1ファイル500行以下`を完了条件にしない。

## 4. 実装順

1. `package.json`、lock、Vite、Vitest、coverage providerを追加する。
2. 現行画面のスクリーンショットと主要操作チェックをベースラインとして記録する。
3. `api`、`shared/format`、`shared/dom`を抽出し、純関数の契約テストを追加する。
4. stateとrouterを抽出する。未保存ガードの入口を一本化する。
5. key-mapping、settings、dashboardを1画面ずつ移す。
6. 残り画面はP2として、変更時または循環依存解消に必要な範囲で移す。
7. CI/リリースからVite buildを実行し、`ui/dist`をGit管理対象から外す。

各移行は、ビルド可能・起動可能・テスト成功の単位でコミットする。

## 5. テスト方針

テスト件数ではなく契約で選ぶ。

- HTML escapeと利用者由来文字列の表示
- 日付境界、期間解決、24時間bucket
- キー表示名と内部identityの分離
- UI倍率の上下限
- routerの未保存ガード
- invoke失敗時のエラー表示
- key-mappingのdirty/save/cancel状態

DOMテストでは`window.__TAURI__`を直接置換せず、`api.ts`をmockする。

## 6. エラーと移行

- `npm ci`失敗時はビルドを失敗させる。既存distへ黙って戻らない。
- Vite移行後も`frontendDist: "ui/dist"`は維持する。
- theme/UI倍率のlocalStorageは、[`PLAN_IDEAS.md`](./PLAN_IDEAS.md)の設定保存方針をreq化するまで既存動作を維持する。
- 到達不能に見える旧画面は、利用箇所を`rg`と実機で確認してから別コミットで削除する。

## 7. 完了条件

- clean checkoutから`npm ci`、test、buildが成功する。
- API、state、router、主要3画面の責務が分離されている。
- 主要契約テストがCIで通る。
- 11画面の表示、未保存ガード、テーマ、倍率の回帰がない。
- `ui/dist`はGit管理されず、CI/リリースで必ず生成される。
