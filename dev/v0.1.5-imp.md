## 1. 目的

# 4. 全要求の事前確認（2026-08-30）

## 4.1 ユーザー回答で確定した仕様

| 論点 | 決定 | 技術的な扱い |
| :--- | :--- | :--- |
| 修飾なし入力の記録禁止範囲 | アルファベット・数字・記号・テンキー数字／演算子は禁止。Modifier単独とWheelも禁止を維持し、ファンクションキー・システムキー・マウスクリックは記録可能 | UIだけでなく `shortcut-core` の最終記録判定とKeyPolicy正規化を同じ分類関数へ統一する |
| 109かな入力 | JIS物理キーのかな刻印をキー表示名に使い、IME変換後文字は取得しない | 入力内容を取得しない既存プライバシー境界を維持し、配列別テンプレートだけを切り替える |
| プロファイル範囲 | 配列、入力モード、キー表示名、修飾パターン別ポリシーを名前付き保存する。作成・上書き・名前変更・削除・適用に対応し、組み込みテンプレートは削除不可 | 組み込みテンプレートはコード内の不変データ、ユーザープロファイルだけを専用JSONへ原子的に保存する。適用時はまずdraftへ反映し、通常の保存操作で確定する |
| 用語 | 利用者向けの「オーバーレイ表示名」を「キー表示名」へ変更する | 既存JSON互換の内部識別子は維持し、UI・通知・文書・表示用formatterを統一する |

## 4.2 コード実測結果

- 自動配置は `overlay/manager.rs::choose_auto_position` がForeground Window 1枚との重複面積最小を選ぶ実装で、表示中の全ウィンドウ、入力フォーカス矩形、条件1と条件2の段階評価は未実装である。
- Security Gateは `security_gate.rs` でUI AutomationのFocused Elementに対する `CurrentIsPassword` だけを確認しており、同じForeground Window内の別コントロールへフォーカスすると保護が外れる。
- Overlay Previewは手動のSAMPLE commandのみで、編集中設定を保存せず渡すAPI、debounce、要求世代管理、外観だけを既定値へ戻す処理がない。
- キーマッピングは保存時に3つの設定を別々に永続化し、draft/savedの差分管理、取消、runtimeだけへの一時反映、離脱防止がない。ウィンドウCloseはWebViewを直ちにdestroyし、Tray終了も未保存状態を確認しない。
- キーマッピング表は分類列が最左ではなく、分類見出し・選択列数ラベル・ブラウザー標準confirmが残っているため `V15-MAP-01`〜`03`は部分実装である。
- 分類は `alnum/modifier/function/system` の4分類で、アルファベットと数字が結合され、記号・マウス・テンキーの独立分類がない。
- 修飾なし記録は `shortcut-core::eligibility::is_recordable` と `KeyPolicyConfig::sanitize` がすべて拒否しているため、確定したキー分類に沿う共通判定へ変更する必要がある。
- キー表示名はNative Overlay内でのみ置換され、Dashboard、ランキング、使用率グラフ、見取り図、詳細画面はDB上の内部shortcut identityを直接表示している。
- Dashboardの「日別利用推移」は `shortcut_daily` を使用しており、全期間を正確に時間帯別集計できるテーブルがない。migration runnerも単一schemaを毎回適用してversion 2へ固定している。
- 日本語109／英語104の配列切替は実装済みだが、入力モード、かな刻印テンプレート、プロファイル永続化は未実装である。

# 6. 要件別・実装方針

## 6.1 `V15-MAP-01`〜`03` キーマッピングレイアウトと一括変更

- 「全キー × 修飾キーパターン」見出しを削除し、検索、見出しなし分類トグル、表の順へ変更する。
- 表列を「分類、キーコード、テキス名、キー表示名、修飾パターン」の順にする。
- 一括変更領域は表と同じ横スクロールコンテナ内に置き、CSS変数または実測した「なし」列offsetへ追従させる。
- 選択列数の常設ラベルを廃止し、未選択時だけ操作時エラーを表示する。
- `window.confirm` を廃止し、中央モーダルに赤字の操作名・行数・列名・セル数を表示する。初期フォーカスとEscapeはキャンセルとする。
- DOMテストまたは静的fixtureで列順、見出し非表示、確認前に値が変わらないことを検証する。

## 6.2 `V15-DATA-01` 時間別集計

- `shortcut_hourly_summary(date, hour, count)` と `(date, hour)` 主キー・date indexをmigrationで追加する。
- migration runnerを現在versionから順に適用する方式へ改め、既存DBを破壊せずversionを進める。失敗はtransaction rollbackする。
- `record_event` transaction内でevent、daily、hourlyを更新する。時間は既存 `RecordableEvent.occurred_at` のローカル値を使用する。
- migration時のbackfillは保持中の `shortcut_events` を実時刻で集計し、日次しかない過去分は生成しない。
- サンプル生成、全削除、指定日以前削除もhourlyと整合させる。詳細履歴retentionではhourlyを削除しない。

## 6.3 `V15-DASH-01`〜`02` Dashboard時間帯別表示

- 選択期間の `shortcut_hourly_summary` をhourで合計し、00〜23を必ず返すAPIを追加する。
- 今日、7日、30日、全期間の既存range解決を再利用し、応答に保持データの開始日を含める。
- Dashboardだけを新APIへ切り替え、Shortcut Detailの日別グラフは変更しない。
- 見出しを選択期間と同時に「今日／過去7日間／過去30日間／全期間の時間帯別利用状況」へ切り替える。
- v0.1.5以前で復元できない期間が含まれる場合は、保持開始日以降の集計である旨を注記する。

## 6.4 `V15-SEC-01` Foreground Window単位のpassword保護

- UI Automation操作をtraitで分離し、Foreground HWNDのRootからDescendantsにpassword propertyを持つ要素が1つでもあるか検査する。
- Focused Elementだけの判定を廃止せず即時判定として残し、Window全体検査結果とORする。
- Foreground HWND変更時、UI tree変更を検知した時、短いTTL満了時に再評価する。UIA/Foreground/Integrity取得失敗はUnknownとしてFail Closedにする。
- Secure Desktop、資格情報shell、高Integrityの既存保護を先に評価し、Overlay/Preview/DB/Realtime Logより前のGateを維持する。
- fake inspectorによる単体テストと、Windows実機用ignored testで「password欄から別欄へ移動しても停止」「別Windowへ移動すると解除」を検証する。

## 6.5 `V15-OVL-01` 条件と順位を分離した自動配置

- 対象monitor上のvisible/non-minimized/non-cloaked top-level windowsを矩形snapshotとして取得し、Overlay自身とアプリの非表示補助Windowを除外する。
- Focused UIA elementが編集可能領域かをcontrol type/pattern/propertyで判定し、BoundingRectangleを取得する。判定不能は入力欄候補なしではなく安全側の評価結果として扱う。
- 候補はpreferredを先頭、残りを保存順で安定列挙し、clampで救済せずWork Area外候補を除外する。
- まず全表示Windowと重ならない候補群A、なければfocused editorと重ならない候補群B、最後にWork Area内の最高順位という段階選択にする。
- pure functionへ矩形一覧を渡す単体テストで優先順位、自己Window除外、境界、同一条件の決定性を固定する。

## 6.6 `V15-OVL-02`〜`03` Previewと外観リセット

- 保存APIとPreview APIを分離し、Preview commandには検証済みdraft configと要求generationを渡す。managerは古いgenerationを破棄する。
- UIの外観関連input/changeを150〜250ms debounceし、入力途中の不正値は送らない。select操作中のDOM再描画は行わない。
- Previewはrendererへ直接渡し、Capture、DuplicateGuard、repeat run、DB、Realtime Log、統計へ接続しない。Security Gate blocked/unknown時は拒否し、表示中Previewも消す。
- 外観リセットは `OverlayConfig::default()` からappearance fieldだけを抽出して現設定へ合成し、位置・monitor・ON/OFF・KeyPolicy・キー表示名を保持する。
- backendで保存成功後だけruntime reloadし、失敗時は旧ファイル/runtimeを維持する。UI確認モーダルの初期フォーカスはキャンセルとする。

## 6.7 `V15-MAP-04`〜`06` draft/runtime/離脱防止

- backendへ `MappingEditSession` を追加し、開始時にmapping/policy/labelsのsaved snapshotとdraftを保持する。
- 有効なUI変更をdebounceして一括draft APIへ渡し、共有KeyMapping/KeyPolicyとOverlayのin-memory label overrideへ反映する。draftはJSON/DBへ書かない。
- 保存は3ファイルを一時ファイルへ出力してから置換し、途中失敗時はbackupから復元する。成功時だけsaved snapshotとdirtyを更新する。
- 取消はsaved snapshotをruntimeへ戻し、UIを再描画する。差分は正規化後の値比較で判定し、元へ戻した場合はdirtyを解除する。
- navigationは `goPage` の入口で止め、WebView CloseとTray終了はbackendのdirty stateでも止めてWindowを表示し、警告eventを送る。未保存破棄の選択肢は設けない。
- 保存・取消中はsessionをbusyにして多重操作、Close、移動を拒否する。

## 6.8 req §25 分類・記録範囲

- 分類を `alphabet/number/symbol/modifier/function/system/mouse/numpad` に分け、フィルターを独立トグル化する。Wheelはmouse表示グループに含めるが記録禁止を維持する。
- `shortcut-core` にVirtual-Key/MainInputから「文字再現リスク」「記録可能な修飾なし入力」を判定する共通関数を置く。
- アルファベット、上段数字、OEM記号、テンキー数字・演算子、Modifier単独、Wheel単独は記録不可とする。F1〜F24、確定したシステムキー、MouseLeft/Right/Middle/X1/X2は単独記録可能にする。
- UIの「記録と表示改行」候補、KeyPolicy sanitize、capture worker最終判定、サンプル母集団を同じ関数へ揃え、設定JSON改ざんでも禁止キーは保存されないようにする。
- 表のfont/input/selectを1段階だけ拡大し、既存のsticky・スクロール・最低表示行数を崩さない。

## 6.9 req §25〜§26 キー表示名の共通利用

- 内部shortcut identityはDB/API/filter/sortキーとして変更しない。
- UI起動時にキー表示名snapshotを読み、`Ctrl+C`等をtoken単位で置換する共通formatterを追加する。
- Dashboard、ランキング、使用率グラフの系列名と一覧、キー×アプリ見取り図、Shortcut Detail、Realtime Log、CSV出力条件の表示へformatterを適用する。DOM data属性とbackend引数は内部identityのままにする。
- 利用者向け文字列を「キー表示名」へ統一し、既存の `overlay_key_labels.json`、`OverlayKeyLabels`、API command名は互換性のため維持する。

## 6.10 req §25 日本語109かな入力

- `KeyboardLayout` と別に `KeyboardInputMode`（romaji/kana）を持たせ、英語104ではromajiへ正規化する。
- 日本語109かなテンプレートはJIS物理キーのかな刻印を内部キー名へ対応付ける。Shift状態やIME変換結果は取得しない。
- 配列／入力モード変更時は、旧テンプレート既定値と一致する項目だけ新テンプレートへ移行し、利用者のカスタム名は保持する。
- UIは「日本語109」を選ぶと入力モード選択を表示し、かな入力を枝分かれで選択できるようにする。

## 6.11 req §25 キーマッピングプロファイル

- 組み込みプロファイルは「日本語109・ローマ字」「日本語109・かな」「英語104」を提供し、読取専用とする。
- ユーザープロファイルはUUID、名前、layout、input mode、labels、policyを持ち、`ShortcutKeyCounter_key_profiles.json` へversion付きで原子的に保存する。
- 名前はtrim、重複禁止、長さ上限、制御文字禁止とする。組み込みと同名も禁止する。
- 適用は現在のmapping edit sessionのdraftへ反映し、保存前警告を表示する。物理Virtual-Key catalog自体は組み込みのためプロファイルへ複製しない。
- UIへ選択、適用、新規保存、上書き、名前変更、削除を追加し、組み込み選択時は変更・削除をdisabledにする。
