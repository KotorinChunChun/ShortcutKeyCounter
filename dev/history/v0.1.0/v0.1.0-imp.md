## デバッグ実行エラー修正反映（2026-08-16）

Tauri commandから統計・設定・CSV・バックアップAPIを呼び出す箇所で、`&db_lock(&state)?` を直接 `command_api` に渡すと、`MutexGuard<rusqlite::Connection>` と `&rusqlite::Connection` の型不一致により E0308（`expected Connection, found MutexGuard`）が発生する問題を反映した。

`apps/shortcut-key-counter/src/tauri_commands.rs` では、DBを利用する各commandを次の形式へ統一する。

```rust
let db = db_lock(&state)?;
command_api::dashboard_summary(&db, start, end)
```

対象は統計照会、除外アプリ、設定、CSV出力、DBバックアップ。既に同形式だった更新系commandも含め、DB参照の書き方を統一した。

再発防止として `scripts/build-release.ps1` に `&db_lock(&state)?` の残存検査を追加し、検出時はcargo build前に失敗させる。

元の修正報告では以下が通過済みだった。今回の更新版についてはChatGPT実行環境にRust/Cargoがないため、Windows側で同じGateを再実行すること。

- `cargo fmt --all -- --check`
- `cargo check --workspace --all-targets --all-features --offline`
- `cargo test --workspace --all-features --offline`
- `cargo clippy --workspace --all-targets --all-features --offline -- -D warnings`
- `cargo build -p shortcut-key-counter -p shortcut-key-capture --offline`
