# 3. 既存セキュリティ仕様

今回のUI変更・ランキング変更・Overlay変更によって、以下を変更しない。

## 3.1 修飾なし単独入力の永続記録禁止

修飾キーなしの単独入力は、キーボード・マウス・垂直ホイール・水平ホイールを問わず永続記録禁止とする。

禁止対象:

- SQLite
- Realtime Logへの実入力イベント投入
- 診断ログ
- テキストログ
- JSON / JSONL
- CSV
- debug print
- crash report
- telemetry
- その他、入力列を後から復元できる保存先

Overlay表示に必要な短時間のメモリ処理のみ許可する。

UIまたは設定ファイルを改ざんしてもruntime Security Gateで必ず拒否する。

---

## 3.2 単独マウスクリックのOverlay表示

一度検討した「単独マウスクリックをOverlay表示対象外にする」変更は撤回する。

以下は修飾なしでもOverlay表示可能とする。

- MouseLeft
- MouseRight
- MouseMiddle
- MouseX1
- MouseX2

ただし修飾なしのためDB・Realtime Log・統計への永続記録は禁止する。

連打時は今回追加するOverlay連打圧縮の対象とする。

例:

`MouseLeft ×8`

---

## 3.3 ホイール単独

以下の修飾なし単独ホイールはOverlayにも表示しない。

- WheelUp
- WheelDown
- WheelLeft
- WheelRight

修飾付きホイールはSecurity Gate通過後、KeyPolicyに従う。

---

## 3.4 Modifier-only

以下の単独押下はOverlayへ表示せず記録もしない。

- Ctrl
- Alt
- Shift
- Win
- 左右Modifier単独

---

## 3.5 Security Gate優先順位

入力処理は概ね次の順を維持する。

1. 計測ON/OFF
2. Security Gate
3. 除外アプリ
4. Overlay候補判定
5. KeyPolicy
6. DB記録判定
7. Realtime Log

password / credential / Secure Desktop / Integrity Level判定に失敗した場合はFail Closedとする。

# 6. Wave 1: 設定画面不具合修正

## 6.1 表示先変更時にコンボボックスが閉じる

### 現象

「表示先」を「デスクトップ」から「アクティブウィンドウ内」へ変更すると、設定保存・runtime反映・SAMPLE preview等によるDOM再描画が発生し、開いているプルダウンが即座に閉じる。

### 修正方針

UI編集中のdraft値と保存済み設定を分離する。

候補状態:

```text
savedOverlaySettings
draftOverlaySettings
isOverlayControlInteracting
previewDebounceTimer
```

処理:

1. `<select>` 操作中はdraft値のみ変更。
2. 不要な画面全体renderを行わない。
3. backend保存成功後も、同一値ならDOMを作り直さない。
4. SAMPLE previewを短時間debounceする。
5. select / input操作中はpreview開始を遅延する。
6. focusを奪わない。

### 受入条件

- プルダウンを最後まで操作できる。
- 選択瞬間にメニューが消えない。
- 設定保存は正常。
- Previewは操作終了後に実行される。

---

## 6.2 固定モニターへ切り替えられない

### 原因想定

`monitor_mode = fixed` を変更した瞬間に保存処理が走り、`fixed_monitor_id` 未指定validationで失敗してUIが旧値へ戻されている。

### 修正

1. `monitor_mode = fixed` をdraft状態にする。
2. モニター番号comboを即時enabled。
3. 接続モニター一覧を表示。
4. モニター選択後に正式保存。
5. モニターが1台のみなら自動選択可。
6. validationは最終保存時に実施。

### 受入条件

- 固定モニターへ切替可能。
- モニター番号comboが即時enabled。
- 選択前に誤エラーを出さない。
- 選択後に安定識別子で保存される。

# 11. Wave 6: Overlay連打圧縮

## 11.1 DuplicateGuardとの分離

Overlay連打圧縮とDB DuplicateGuardは完全に別機能として実装する。

```text
Capture
  ↓
Security Gate
  ↓
Overlay eligibility
  ├─ Overlay Repeat Compressor
  │      ↓
  │    Overlay renderer
  │
  └─ Recording eligibility
         ↓
     DuplicateGuard
         ↓
        DB
```

Overlayカウンターは物理入力回数を表す。

DB DuplicateGuardはDB記録抑制のための機能であり、Overlayカウントには影響させない。

例:

物理的に `Ctrl+C` を10回押した場合、Overlayは:

`Ctrl + C ×10`

と表示可能。

DB側ではDuplicateGuard設定によって保存件数が10未満でも仕様上正常とする。

---

## 11.2 連打開始

1回目:

`A`

2回目:

`A A`

3回目:

`A ×3`

4回目以降:

`A ×4`

`A ×5`

...

3連打以上で圧縮開始する。

---

## 11.3 連打判定時間

確定仕様:

**700ms**

同一normalized identityが直前入力から700ms以内に続いた場合、同一連打runとして扱う。

別入力または700ms超過でrun終了。

---

## 11.4 identity

表示文字列ではなくnormalized identityで判定する。

例:

- `A`
- `Ctrl+C`
- `MouseLeft`
- `Alt+WheelRight`

表示名を変更しても連打判定は変わらない。

---

## 11.5 run終了条件

- 別identity入力
- 700ms超過
- Overlay session終了
- Security Gate遷移
- Overlay OFF
- Preview開始

---

## 11.6 カウントアップアニメーション

# 14. 前日分Realtime Logサンプル

## 14.1 目的

サンプルデータ生成後にRealtime Log画面の見た目・件数・表示動作も検証可能にする。

確定仕様:

**前日分についてRealtime Log表示用サンプルも生成する。**

---

## 14.2 Security Ruleとの整合

Realtime Log用として、修飾なし単独入力を別ログへ永続化してはならない。

Realtime Logへ出してよいサンプルは、Security Gate上「DB記録可能なショートカット」に相当するものだけとする。

つまり:

- 修飾付きショートカット中心
- DisplayOnlyは除外
- Ignoreは除外
- 修飾なし単独入力は除外

---

## 14.3 実装方式

Realtime Log専用の入力履歴テーブルを新設するのではなく、**検証DBへ生成した前日分のDB記録対象サンプルイベントからRealtime Log表示用データを構成する**。

これにより「Realtime LogはDB記録対象だけ」という既存原則を維持する。

実装候補:

1. サンプル生成完了後、前日分 `shortcut_events` のうち最新N件をRealtime Log view-modelへ読み込む。
2. または検証モード専用の「前日サンプルRealtime Logロード」処理を用意する。

通常Capture経路へ偽入力を注入しない。

# 15. Overlay退避クリック

## 15.1 click-through

Overlay Window自体を通常クリック可能Windowへ変更しない。

既存のglobal mouse captureから:

1. Overlay表示中か
2. MouseLeft座標がOverlay bounds内か

を判定する。

背面アプリへのWindows clickはブロックしない。

---

## 15.2 反対位置

確定マッピング:

| 現在 | 移動先 |
|---|---|
| 左上 | 右下 |
| 上中央 | 下中央 |
| 右上 | 左下 |
| 左中央 | 右中央 |
| 中央 | **右下** |
| 右中央 | 左中央 |
| 左下 | 右上 |
| 下中央 | 上中央 |
| 右下 | 左上 |

中央 → 右下で確定する。

---

## 15.3 Overlay退避クリックの記録禁止

Overlay退避クリック判定が成立した場合、そのMouseLeftは**修飾付きでもShortcutKeyCounterの入力イベントとして完全に破棄する**。

禁止:

- DB
- Realtime Log
- Overlay入力キャップ
- 統計
- shortcut_daily
- 診断ログへの入力内容

例:

Ctrlを押しながらOverlay上をクリックしても:

`Ctrl + MouseLeft`

として記録しない。

ただしWindows上の元クリックはclick-throughで背面アプリへ届く。

# 20. 懸念点

仕様上の未確定事項は現時点で実装を止めるものはない。

ただし実装時に以下を重点確認する。

## 20.1 Realtime Logサンプル

通常Realtime Logは「現在発生したDB記録対象イベント」を表示する機能であるため、前日データを表示する場合は通常Captureと混同しないUI上の扱いが必要。

推奨:

- 検証DB時だけ利用可能
- サンプル由来であることを表示
- 通常の実入力イベントとして再注入しない

---

## 20.2 連打圧縮 vs DuplicateGuard

Overlay上の `×N` とDB保存件数は一致しない場合がある。

これは仕様どおりであるため、実装コード・テスト名・コメントでも2機能を明確に分離する。

---

## 20.3 平均値

旧コードの平均定義が見つかった場合は必ず既存定義を採用し、今回計画のfallback定義へ勝手に置き換えない。

---

## 20.4 60日サンプルと性能

約10,000件自体は大きくないが、ランキング比較・グラフを毎回eventsから再計算すると将来実データで性能劣化する。

集計テーブルとindexを前提に実装する。

---

## 20.5 グラフ色永続化

キー表示名変更後も色が維持されるよう、表示ラベルではなく内部identityへ紐づける。
