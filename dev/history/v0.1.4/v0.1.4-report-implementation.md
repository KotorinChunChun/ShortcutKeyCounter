# ShortcutKeyCounter v0.1.4 実装報告

作成日: 2026-08-18
ベースライン: v0.1.3 ユーザー修正版（build fix反映済み）
UI基準: `ShortcutKeyCounter_bugfix_ui_mock_v3.html`（実装時に受領した外部参照。本リポジトリには含めない）

## 1. 実装概要

v0.1.4計画に沿って、設定runtime化、キーマッピング検索、ランキング統合、使用率グラフ、Overlay連打圧縮、60日サンプル生成を既存Rust/Tauri構成へ統合した。

## 2. 設定runtime化

- `duplicate_guard_seconds` をsettingsへ追加。0.0〜10.0秒をruntimeで反映し、0で無効化できる。
- `detail_event_retention_days` をsettingsへ追加。起動時retentionが固定7日ではなく設定値を参照する。
- `usage_graph_colors` をsettingsへ追加し、系列の内部identity別カラーを永続化する。
- Overlay設定保存後の自動SAMPLE previewを廃止し、select/input操作時のfocus喪失を防いだ。
- 固定monitorへの切替はdraft状態を許容。複数monitor時はplaceholderを表示し、対象選択前にvalidationで旧値へ巻き戻さない。
- 保存済みmonitor IDが接続一覧に存在しない場合はUI上の選択をクリアし、複数monitor環境で別monitorを勝手に選ばない。

## 3. キーマッピング

- テーブルを独立scroll領域へ変更。
- 分類filterと一括変更controlを横並びに整理。
- 修飾列0件では一括変更APIを呼ばない。
- `KeySearchCapture` を追加。検索開始後の次の物理入力をCapture workerで消費し、該当identityだけをUIへ返す。
- 検索入力はSecurity Gate通過後、除外判定/Overlay/KeyPolicy/DB/Realtime Logより前にreturnするため通常入力経路へ流れない。

## 4. ランキングbackend

`apps/shortcut-key-counter/src/analytics.rs` を追加した。

- Today / 7 days / 30 days / All の期間model。
- Todayは前日の同時刻までを比較対象とする。
- Key ranking: count / average / ratio / comparison rate。
- application filterは行filterではなくSQL集計から再計算する。
- All + application filterの平均分母はfilter後のデータ存在日数。
- Application ranking: count / key type count / active seconds / ratio / comparison rate。
- Usage Graph: Today=hour、7/30=day、All=monthをSQLiteで集計し、欠損bucketは0埋めする。

Tauri command:

- `get_rankings_v014`
- `get_usage_graph_v014`
- `get_usage_graph_colors`
- `set_usage_graph_colors`

## 5. ランキング/グラフUI

UI mock v3の構造を実装基準として反映した。

- 左navの「計測結果」配下へRealtime Log / Ranking / Usage Graph / Matrixを配置。
- Rankingはdesktop幅でキー別/アプリ別の左右2ペイン。
- 今日 / 7日 / 30日 / 全期間切替。
- キー別の対象アプリcombo。
- 3-state sort: 降順 → 昇順 → なし。
- 利用時間を日本語表示。
- Usage Graphはキー/アプリ切替、上位5系列初期ON、系列ON/OFF、Canvas折れ線描画、色変更/永続化を実装。

## 6. Overlay Repeat Compressor

Overlay managerへDB DuplicateGuardとは独立したrepeat stateを追加した。

- 判定間隔: 700ms。
- normalized identity単位でrun管理。Security Gateが閉じた入力を検知するとOverlay sessionを破棄し、保護領域の前後でrunを継続しない。
- 1回目: 通常。
- 2回目: 同一トークンを2件表示。
- 3回目以降: 1件へ圧縮して `×N`。
- keyboard shortcut、単独表示key、MouseLeft等で同じ方式を利用。
- count更新時のみ220msのbump animationを実行し、既存tokenのIN/OUT animation clockは再起動しない。

Repeat counter theme schema:

- background color
- text color
- accent/shadow color
- badge shape
- rotation
- font size

`overlay-theme.json` schema versionをv3へ移行し、旧v2はdefault付きで読み込み後v3へ安全に書き戻す。破損JSONは従来どおり保護する。

## 7. Overlay退避クリック

既存のglobal mouse capture + Overlay bounds判定を維持し、退避click判定成立時はCapture workerで通常処理へ進めずreturnする。

- center → bottom-rightを維持。
- modifier付きMouseLeftでもDB/Realtime Log/Overlay input/statisticsへ入れない。
- Native Overlay自体はclick-through/no-activateを維持するため背面applicationの元clickは妨げない。

## 8. サンプルデータ

- Test DB以外ではcommand層で拒否。
- Production DBからdistinct application/shortcutを取得。
- 母集団shortcutは「modifier + primary key」を持つものだけに限定し、旧履歴のunmodified入力やModifier-onlyを再生成しない。
- 前日を終端に60日、約10,000eventをweekday/long-tailの偏り付きで生成。前日Realtime Log検証を確実に行えるよう、event_countのうち最大200件は前日へ保証配置する。
- `shortcut_events` と `shortcut_daily` を同一transactionで整合更新。
- `application_usage_daily` も60日生成し、1日のaggregateが24時間を超えないようbudget制御。
- 前日分Realtime LogはTest DBの生成済み`shortcut_events`最新200件をin-memory viewへ読み込む。通常Captureへ偽入力は注入しない。

## 9. v0.1.3 build fix維持

- workspace `windows.workspace = true` 等の依存関係修正を維持。
- Overlay Pixmapの`Arc<Pixmap>`整合を維持。
- 既存Clippy修正を後戻りさせていない。
- settings初期値が8件へ増えたためstartup/maintenanceの旧期待値を更新した。

## 10. 検証上の制約

この実装環境にはRust/CargoおよびWindows Native runtimeがないため、Rust build/check/clippy/testとWin32実機試験は未実施。TypeScript、設定/manifest parse、SQLite query/migration、静的regression gateは本環境で確認する。Windows側では `scripts/build-release.ps1` と [v0.1.4 Windows受入試験チェックリスト](./v0.1.4-checklist-windows-acceptance.md) を必ず実施する。

## 2026-08-18 実機確認後の追加修正

実機スクリーンショットで確認された以下を追加修正した。

- サンプルデータ生成を独立乱数方式から行動モデル方式へ変更。
  - 平日/休日の利用差、前日からの連続性、60日間の習熟トレンド、複数日の作業ピークを導入。
  - アプリ・ショートカットをLong-tail分布とし、アプリごとの曜日特性・キー相性を付与。
  - 下位ショートカットは習得開始時期をずらし、後半ほど利用種類が増えるようにした。
  - application_usage_daily をショートカット活動量と相関させた。
  - 前日Realtime Log用200件保証は維持。
- ランキング画面から開発用説明文「対象アプリで集計値そのものを再計算」「上位カードを廃止し、一覧へ統合」を削除。
- キーマッピングの「キーを入力して検索」を「全キー × 修飾キーパターン」見出し右へ移動。
- 「n/nキー表示 × 16パターン / 選択 n列」の内部状態表示を削除。
- キー検索にWebView側のkeydown/mouse/wheel fallbackを追加。backend Capture search modeは引き続き入力をDB/Realtime Log/Overlay/統計へ流さない。
- Lightテーマの位置選択セルで、一般ボタン背景がactive色を上書きするCSS specificity不具合を修正。
- Light/Darkテーマ別のスクロールバー色を明示し、Lightテーマで黒いスクロールバーが残らないようにした。
