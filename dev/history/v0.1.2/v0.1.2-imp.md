## 0. 事前確認（実測結果）

### 0-1. 仕様の判断

追加質問は不要だった。タスク文書の依存順と既存実装から、次を採用する。

| 論点 | 決定 | 根拠 |
| :--- | :--- | :--- |
| Overlay設定のSource of Truth | `settings.overlay_enabled` はSQLite、表示設定は `overlay-theme.json`、表示名は `overlay_key_labels.json`、ポリシーは `overlay_key_policy.json` | OVL-11/13の最終方針。JSONのlegacy `enabled`は読み込み互換のみとする |
| 既存v1テーマ | 起動時にv2へ変換し、temp→flush→renameで書き戻す。破損JSONは上書きせずdefaultへfallback | OVL-13の移行・保全条件 |
| 単独キーの内部名 | 既存 `shortcut-core::key_names` の安定キー名を再利用 | DB/key mapping/表示名のidentityを変えないため |
| 単独キーとキーマッピング | Overlay候補は先に生成・表示し、DB記録だけ既存Key Mappingを適用する | OVL-06の単独キー表示と既存DB記録条件を両立するため |
| 設定反映 | JSON/SQLite保存後に既存Overlay threadへreload commandを送る | Overlay Window/threadを再生成しない条件を満たすため |

### 0-2. 現行コードの切り分け

- `apps/shortcut-key-counter/src/overlay/config.rs` はv1の `hold_ms` / `max_items` / bottom-center固定。
- `overlay/manager.rs` は記録対象shortcutだけを文字列で受け、固定TTL・固定3行・固定中央下描画を行う。
- `capture_worker.rs` は `is_recordable` の後でOverlay通知しているため、通常キーがOverlayへ届かない。
- `settings.rs` / `settings_repository.rs` にSQLiteの `overlay_enabled` は既に存在する。
- `tray.rs` は計測ON/OFFのみで、Overlay専用トグルは未実装。
- `ui/index.html` / `ui/src/main.ts` はv0.1.1のOverlay ON/OFFとJSON再読み込みだけを提供する。
- `crates/shortcut-windows/src/overlay_window.rs` は `rcWork`、Per-monitor DPI、`WS_EX_NOACTIVATE`、`HTTRANSPARENT`を既に保持している。

## 2. 要件別・実装方針

### 2-1. OVL-01 設定モデル拡張

- `OverlayConfig`をv2として追加し、既存描画用のkey/design設定を保持したまま、時間・位置・背景・行数・animationを型付きで追加した。
- `OverlayThemeConfig`は既存呼び出しとの互換aliasとして残す。
- `sanitize`で指定範囲をclampし、破損JSONは既存のdefault fallbackを維持する。
- 旧v1のnested JSONは明示的にv2へmigrationする。

### 2-2. OVL-02 表示時間設定

- `OverlayTiming`と`phase_at`を純粋関数として追加する。
- stable時間は `display_duration_ms`、IN/OUT時間はanimation設定から計算する。
- single-key sequenceは`last_input_at`をTTLの基準にできる構造にする。

### 2-3. OVL-03 9位置レイアウト

- `OverlayPosition`を共通型にし、`WorkArea` / `Size` / `Point`と`calculate_overlay_origin`をWindows crateへ追加する。
- managerは既存の`rcWork`とDPIスケールを使い、position modeがfixedのとき9位置へ配置する。

### 2-4. OVL-04 自動位置ローテーション

- `AutoPositionState`をmanager thread内に保持し、全Item消滅時だけindexを進める。
- 同一sessionの全行は同じpositionを使い、fixed切替時はactive sessionを破棄する。reload時の既存行はmax_rowsへtrimして保持する。

### 2-5. OVL-05 背景色・透明度

- `#RRGGBB`のparse、opacityのclamp、premultiplied alpha対応をconfig/rendererへ追加する。
- managerのcanvasにpadding付き角丸背景を先に描画し、キーキャップのalphaとは分離する。

### 2-6. OVL-06 単独キーOverlayEvent

- `OverlayInputKind`と`OverlayEvent`を追加し、normalized shortcutの有無を保持する。
- 既存key name mappingから通常キーを作り、modifier-onlyとShift単独のノイズは既定で抑制する。
- Overlay candidate生成はDB記録可否・Key Mappingより前に行う。foreground/exclusionはcandidateを表示へ流す前に確認し、Key MappingはshortcutのDB記録にだけ適用する。

### 2-7. OVL-07 KeyPolicy表示/記録分離

- `KeyAction`、`KeyDecision`、`KeyPolicyConfig`、`overlay_key_policy.json`を追加する。
- 既定値はsingle key=`DisplayOnly`、従来shortcut=`DisplayAndRecord`、overrideをidentity単位で適用する。
- DisplayOnly/IgnoreはDB、ranking、daily、application stats、realtimeの記録成功系へ流さない。

### 2-8. OVL-08 単独キー横連結

- Overlay itemを`Shortcut` / `SingleKeySequence`とtokensへ拡張し、700ms以内かつ20token未満なら同一行へ追加する。
- shortcutは必ず新規行、追加時はsequenceの`last_input_at`を更新する。
- rendererにtoken列描画を追加し、max row widthとtoken上限で無限拡張を防ぐ。

### 2-9. OVL-09 IN/OUT animation

- `animation.rs`へTransform、easing、enter/exit transform、0ms progressを追加する。
- managerはphaseごとのpresetを選び、stable時はtimer/redrawを抑制する。

### 2-10. OVL-10 最大行数

- `max_rows`を1〜10でsanitizeし、追加時・設定reload時にlogical rowsだけをtrimする。
- sequenceは1行として扱い、window高さは実際の行数から計算する。

### 2-11. OVL-11 クイックOFF

- SQLite `overlay_enabled`を唯一の永続Source of Truthとして、OverlayHandleのAtomicBoolとthread commandへ反映する。
- trayにOverlay toggleを追加し、OFF時はitems/window/timerを即時停止する。Capture/DBは継続する。
- UI/trayへ`overlay-enabled-changed`をemitし、WebView未生成でもtray操作できるようにする。

### 2-12. OVL-12 設定画面・UI/API

- `OverlaySettingsDto`とget/set Tauri commandを追加し、validate/sanitize→JSON/SQLite保存→runtime reloadの順で適用する。
- 9位置grid、fixed/auto、duration、max rows、background、IN/OUT、animation duration、single-key actionをUIへ追加する。
- frontendはselect/toggleを即時、入力値をchangeで保存し、backendでもsanitizeする。既定値に加えて代表キーの検索可能なpolicy一覧とJSON編集APIを接続する。

### 2-13. OVL-13 移行・結合テスト

- v1テーマ移行、初回policy生成、JSON保全、DB identity不変、旧dedup/exclusion/window条件のunit回帰を追加する。
- build-releaseの旧v0.1.1 static gateをv0.1.2の名前へ更新し、WebView Overlay混入を引き続き拒否する。

### 2-14. 追加要望（表示先・モニター・全キーのポリシー表・入力拡張）

- `OverlayDisplayMode`でデスクトップ表示とアクティブウィンドウ内表示を選択できるようにした。既定値は従来どおりデスクトップ表示とする。
- デスクトップ表示時のモニターをアクティブウィンドウのモニターまたは固定モニターから選択できるようにした。モニター一覧はWin32の実モニター情報から取得し、既定値はアクティブウィンドウのモニターとする。
- `MouseMiddle`をcore/common/Windows hook/IPC/UIのマッピング対象へ追加した。既存設定JSONで項目が欠落している場合は有効として読み込む。
- Shift単独を含む修飾キー組み合わせをCapture workerまで渡し、KeyPolicyで記録・表示を個別に選択できるようにした。
- 「よく使うキーの個別設定」を廃止し、キーマッピング画面へ全キー×16修飾パターン（Ctrl/Alt/Win/Shiftの全組み合わせ）の表を配置した。選択肢は「なし」「続けて表示」「表示して改行」「記録と表示改行」とした。
- 既定値は単独キーを「続けて表示」、修飾キー付きショートカットを「記録と表示改行」とし、連続する単独キーは同一行へ`A B`形式で連結する。既存の旧アクション名はaliasで読み込む。
- OEM記号、ファンクションキー、テンキー、ブラウザー／メディア系などのキー名カタログを拡張し、キーマッピング表へ反映した。

## 4. 実装で判明した追加対応

- 既存プロジェクトのGitメタデータが存在せず、Waveごとのbranch/commitは作成できない。変更と検証結果は本書へ残した。
- `build-release.ps1`は`pwsh`呼び出しへ統一し、v0.1.2 Overlay/Policy/Tray同期の静的Gateを追加した。
- ユーザー指定に従い、release build開始前に`Get-Process -Name ShortcutKeyCounter | Stop-Process -Force`相当で実行中EXEを強制終了し、ロックを解消したうえでrelease build・ZIP生成を実行した。
- UIのTypeScript compilerはworkspaceに未配置だったため、一時ディレクトリのTypeScriptでstrict buildを実行し、`ui/dist`へ生成物を反映した。
- 固定モニターの位置計算はモニターのwork areaを使用し、固定モニターのDPI情報が取得できない環境では96 DPIへfallbackする。アクティブウィンドウ表示では対象ウィンドウのclient areaとDPIを使用する。
