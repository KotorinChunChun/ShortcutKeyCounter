## 1. 目的

- UIを使わず、固定seed・固定日付から再現可能なSQLite fixtureを生成する。
- 本番DBと通常の検証DBを一切開かない。
- D06が実行ごとの一時データディレクトリを利用できるようにする。

「DBファイルのバイト一致」はSQLite内部状態に依存するため保証しない。正規化したテーブル行と集計結果の一致を保証する。

## 2. v0.2.0対象

| シナリオ | 内容 | 用途 |
|---|---|---|
| `empty` | migration済み、統計0件 | 初回・空状態 |
| `light` | 7日、約500イベント、固定カタログ | 通常E2E |
| `boundary` | 月/年/23:59:59.999/00:00境界 | 集計境界 |

`heavy`、`multi-app`、`large`は性能上の実課題が確認された時点でP2追加する。100万件生成を通常リリースゲートにしない。

## 3. 既存資産の再利用

`sample_data.rs`の分布、集計、Security不変条件を再利用可能な純粋コアへ抽出し、次を引数化する。

- seed
- end date
- event count
- application/shortcut catalog

同じ生成ロジックを複製しない。UIサンプル生成は時刻seedと既存本番カタログを、テストfixtureは固定seedと固定カタログを渡す。

## 4. 出力先の安全設計

任意の`--db`は受け付けない。呼出側が`New-TemporaryFile`相当で作った一時rootを渡し、ツールがその直下にランダムな子ディレクトリと`ShortcutKeyCounter.e2e.test.db`を作る。

```text
testdata create
  --scenario light
  --seed 42
  --end-date 2026-08-29
  --temp-root <OS temporary root>
```

出力JSON:

```json
{"scenario":"light","seed":42,"data_dir":"...","db_path":"...test.db","events":500}
```

DBを開く前に次を検証する。

- `temp-root`がOSの一時ディレクトリまたはCIが明示した許可root配下である。
- 作成した子ディレクトリのcanonical pathがroot配下である。
- DB名が固定の`.test.db`名である。
- `ShortcutKeyCounter.db` / 通常`ShortcutKeyCounter.test.db`と一致しない。

既存ファイルへの追記・resetはP1では提供しない。毎回新規ディレクトリを作る。

## 5. 配布境界

- dev専用bin `testdata`をfeature gate付きで追加する。
- 通常Tauri build、MSIX、ZIPへ含めない。
- 通常アプリ本体にデータ生成CLIを追加しない。
- release構成でfeatureが無効であることをCIで確認する。

## 6. 整合性とSecurity

- 生成イベントは通常のrecord eligibilityと同じcore判定を通す。
- `shortcut_events`、daily、hourlyの合計が一致する。
- 記録禁止対象の修飾なし英数記号入力、password、window title、URL、パスをfixtureへ含めない。
- `boundary`の時刻はDBの実フォーマットと同じ精度で保存する。

## 7. テスト

- 同一seed/dateの2DBで、ORDER BYした全テーブル行が一致する。
- seed違いでイベント分布が変わる。
- empty/light/boundaryの集計整合性が成立する。
- 許可root外、既存DB、本番名、symlink/junction経由をDB open前に拒否する。
- 通常ビルド成果物にtestdata binaryが含まれない。

## 8. 完了条件

- 3シナリオを新規一時ディレクトリへ生成できる。
- 本番・通常検証DBのhashが実行前後で不変である。
- 行レベルの決定論と集計整合性テストが通る。
- D06が出力`data_dir`を明示してアプリを起動できる。
