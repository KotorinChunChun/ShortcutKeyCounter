## 1. 目的

- v0.1.5リリース前に、現在ローカルだけで行っている品質確認を最小CIへ載せる。
- v0.2.0でNode依存、TSテスト、静的ゲート、成果物生成を再現可能にする。
- セキュリティ製品自身のCIとして、第三者Actionと`GITHUB_TOKEN`の権限を最小化する。

## 2. 段階導入

### 2.1 v0.1.5リリース前の最小CI

Windows runnerで次を直列または小数ジョブで実行する。

1. checkout
2. `cargo fmt --all -- --check`
3. `cargo check --workspace --all-targets --all-features`
4. `cargo test --workspace --all-features`
5. 現行`build-ui.ps1`
6. `dev/scripts/test-release-ShortcutKeyCounter-all.ps1`内の静的回帰ゲート

現行ブランチがfmtを通らない状態ではCIを有効化しない。まずv0.1.5の整形を完了する。

### 2.2 v0.2.0本格CI

| ジョブ | 内容 | 必須 |
|---|---|---|
| rust | fmt / clippy / check / test | 必須 |
| ui | `npm ci` / Vite build / Vitest | 必須 |
| static-gate | `dev/scripts/test-quality-gate.ps1` | 必須 |
| e2e-smoke | D06の安全な一時データで起動スモーク | v0.2.0リリース時必須、pushごとは実測後判断 |
| coverage | Rust/TSカバレッジ生成 | 監視。数値ゲートは別途合意時のみ |

## 3. セキュリティ要件

- workflow先頭に`permissions: contents: read`を明示する。
- `pull_request_target`を使用しない。
- 外部Actionは、実装時に正規リポジトリのfull commit SHAへ固定し、コメントに版を記す。
- release、Store、証明書関連secretは通常CIへ渡さない。
- fork由来PRで書込み権限やsecretを使用しない。
- PowerShellはすべて`pwsh`で実行する。

GitHub公式: [Secure use reference](https://docs.github.com/en/actions/reference/security/secure-use)

## 4. 静的回帰ゲート

`dev/scripts/test-release-ShortcutKeyCounter-all.ps1`の既存`Select-String`群を`dev/scripts/test-quality-gate.ps1`へ移し、CIとリリース検証から同じものを呼ぶ。

静的文字列ゲートは補助であり、次の優先順で置換する。

1. Rust/TSの振る舞いテスト
2. 型・API境界のコンパイル検証
3. 置換できない構造だけ静的ゲート

文字列が存在するだけで安全性を証明した扱いにはしない。

## 5. UI成果物

- D02移行中は、コミット済み`ui/dist`と再生成結果の差分を一時的に検証する。
- D02完了後は`ui/dist`をGit管理対象から外し、CIとリリースが毎回ソースから生成する。
- Nodeがない環境で既存distへフォールバックして成功扱いにしない。

## 6. カバレッジ

導入する場合は次を明示する。

- Rust: `cargo-llvm-cov`の固定版と対象パッケージ
- TS: Vitestのcoverage provider（例: `@vitest/coverage-v8`）
- 除外対象: Win32薄いラッパー、生成物
- 比較方法: 基準ブランチからの低下を監視

「Security関連90%」のような数値をゲートにする前に、行/branch/functionのどれを分母にするかをreqで決める。v0.2.0ではレポート生成を目標とし、未達だけでビルドを落とさない。

## 7. 完了条件

- 最小CIがv0.1.5の実コードでグリーンになる。
- 本格CIが最小権限、full SHA固定、同一refキャンセルを満たす。
- CIとローカルの実行コマンドが一致する。
- UI成果物とテスト結果がソースから再現される。
- 失敗時に再現コマンドがログから分かる。
