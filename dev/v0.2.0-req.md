# v0.2.0 要求仕様

作成日: 2026-08-30  
最終改訂日: 2026-08-30  
ステータス: 次期版計画。v0.1.5リリース後に着手

## 1. 目的

利用者向け機能を原則としてv0.1.5から変えず、CI、フロントエンドの再現可能なビルド、契約テスト、安全なfixture、E2Eスモークを整備し、以後のMSIX対応と機能改善を安全に進められる基盤を作る。

## 2. 着手条件

- v0.1.5の要求・実装・受入確認が完了している。
- v0.1.5の最小Windows CIがグリーンである。
- v0.1.5がリリース済みで、版付き資料が`dev/history/v0.1.5/`へ移動済みである。

## 3. 要求

### REQ-V20-001 MSIX・E2E技術スパイク

- 自己署名MSIXをクリーンVMで起動できることを確認する。
- WebView2、Low Level Hook、Security Gate、StartupTask、パッケージデータ領域、ポータブル版からの移行を実測する。
- `@wdio/tauri-service`を第一候補として、一時データ領域を使う起動スモークを通す。
- 前提が成立しない場合は全面実装へ進まず、設計を改訂する。

### REQ-V20-002 CIとフロントエンド再現性

- CIを最小権限で実行し、外部Actionをfull commit SHAで固定する。
- Node.js依存を`package.json`とlockファイルで固定する。
- Viteで`ui/dist`をソースから再現生成し、Vitestで主要な純関数と画面状態を検証する。
- 移行完了後は`ui/dist`をGit管理せず、CIとリリース工程で生成する。

### REQ-V20-003 契約テストと最小リファクタリング

- `command_api`の主要な統計、設定、キーマッピング契約を自動テストする。
- 修飾なし英数記号入力の記録禁止判定を`shortcut-core`へ集約する。
- ファイル行数を目的にせず、テストで挙動を固定できた責務だけを分割する。

### REQ-V20-004 安全なfixture

- `empty`、`light`、`boundary`のfixtureを固定seed・固定日時で生成する。
- 出力先は実行ごとの一時領域に限定し、許可範囲外や本番DB名をDB open前に拒否する。
- fixtureでもSecurity Gateとデータ最小化の不変条件を守る。

### REQ-V20-005 Fail ClosedのE2E

- E2E専用データディレクトリ、DB、単一インスタンス名前空間を通常版から分離する。
- E2E設定が欠落・不正な場合はDBやCaptureの初期化前に起動を拒否し、本番設定へフォールバックしない。
- 起動、ダッシュボード、設定、キーマッピングの未保存ガードをP1スモークとして自動化する。

### REQ-V20-006 リリース品質

- P0/P1タスク、Rust/TypeScriptテスト、E2Eスモーク、縮小版Windows実機受入、旧DB回帰を完了する。
- Security Gateとデータ最小化の回帰ゲートをすべて通す。
- 単純な行数、テスト件数、自動化率だけを完了条件にしない。

## 4. 対象外

- Microsoft Storeへの本提出
- 全11画面のE2E網羅
- テーマ／プロファイル共有
- オンライン同期、統計自動送信、アプリ内AI、コード実行型プラグイン
- macOS、Linux、モバイル対応
