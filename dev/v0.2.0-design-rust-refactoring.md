## 1. 背景

`overlay/manager.rs`、`tauri_commands.rs`、`capture_worker.rs`は大きいが、行数だけでは障害ではない。より重要なのは、Tauri command契約のテスト不足と、修飾なし英数記号の記録禁止判定が複数層に分かれていることである。

大規模な機械分割を先に行うと、macro登録漏れ、可視性変更、Security Gate順序変更を検出できない。そのためテストを先に追加する。

## 2. P1: v0.2.0必須範囲

### 2.1 command_api契約テスト

in-memory SQLiteと既存migrationを使い、次の利用者契約をテストする。

- 空DBとデータありDBのdashboard/ranking
- 日付範囲と24時間bucket
- 設定値のvalidationと保存
- CSVフィルターと安全な出力名
- mapping editのsave/cancel/rollback
- エラーコードと利用者向けメッセージの代表例

85コマンドすべてを件数目標でテストするのではなく、共通helperと高リスク経路を優先する。

### 2.2 セキュリティ判定の統合

VK版とidentity版の「修飾なし英数記号の記録禁止」を`shortcut-core`に集約する。

- capture workerとKeyPolicy sanitizeが同じcore APIを呼ぶ。
- 文字、数字、記号、テンキー、Wheel、Fキー、system key、mouseの対応表をテーブルテストにする。
- Security Gate後、record強制拒否、Realtime Logへの流入禁止を既存テストで固定する。

## 3. P2: 必要時に行う分割

### 3.1 Tauri commands

command_apiテスト後、変更頻度の高い`mapping`、`settings`、`data`から分割する。全commandの一括移動は避ける。

分割コミットごとに次を確認する。

- `generate_handler!`登録漏れがない。
- command名、引数、戻り値、エラーコードが不変。
- UIから対象画面を起動するスモークが通る。

### 3.2 capture pipeline

Security Gateの処理順を読み取れる小さな関数へ抽出する。分割後も次の順序を固定する。

```text
capture enabled
→ Security Gate
→ key search消費
→ excluded app
→ overlay退避クリック消費
→ normalize/policy
→ 修飾なし英数記号のrecord強制拒否
→ overlay
→ mapping/duplicate guard
→ DB
→ Recorded時だけRealtime Log
```

### 3.3 overlay manager

配置計算、item/repeat、描画、thread/handleのうち、変更対象となる責務だけを抽出する。実描画、click-through、DPI、複数monitorは分割後にWindows実機で確認する。

### 3.4 trait化

追加したいテストがWin32境界で書けない場合に限り、最小traitを導入する。将来利用を予想した抽象化は行わない。

## 4. 禁止事項

- リファクタリングと挙動変更を同じコミットに混ぜない。
- ファイル行数を目的にpublic APIを増やさない。
- エラーコード・文言をついでに変更しない。
- Security Gate、Fail Closed、data minimizationの順序を変えない。

## 5. 完了条件

### v0.2.0 P1

- command_apiの主要契約テストがある。
- 修飾なし英数記号の記録禁止がcoreの単一APIへ統合される。
- 既存203件以上の意味的テストが失われず、全workspace testが通る。
- Windows縮小スモークで計測、Overlay、統計、設定、CSVが動く。

### P2分割

- 分割対象の変更理由とテストが先に存在する。
- 対象APIと利用者挙動が不変である。
- 実機依存箇所を受入記録へ残す。
