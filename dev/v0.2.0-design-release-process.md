作成日: 2026-08-30  
最終改訂日: 2026-08-30  
対象範囲: v0.2.0以降（最小CIのみv0.1.5へ前倒し）  
ステータス: 方針確定  
関連文書: [要求仕様](./v0.2.0-req.md) / [実装計画](./v0.2.0-imp.md) / [テスト戦略](./v0.2.0-design-test-strategy.md)

## 1. 工程

```text
要求 → 設計 → 技術スパイク（必要時） → 実装 → 検証 → リリース → 公開後確認
```

外部仕様、Store審査、Windows実機、未知APIを前提とする場合、全面実装前に期限付きスパイクを置く。

## 2. 要求・設計

### 着手条件

- ユーザーが`dev/vX.Y.Z-req.md`を確定している。
- 前版の必須項目が完了、または明示的に繰越されている。
- 要件ID、受入条件、Security/Store影響が記載されている。
- 不明点がQ&Aへ記録されている。

### 設計完了条件

- 影響する設計書とdecision logが同期している。
- 対象ファイル、境界、migration、failure mode、検証方法がimpへ記載されている。
- 外部前提は公式資料とスパイク項目が示されている。
- テスト件数や行数ではなく、利用者シナリオの期待結果がある。

## 3. 技術スパイク

### 適用例

- MSIX manifest、Store Capability、StartupTask
- WebView2、LL hook、UAC
- Tauri/WebDriverの新しい接続方式
- 大量DB性能

### 完了条件

- 時間上限、入力、環境、Pass/Fail条件がある。
- 結果をimpへ記録する。
- Fail/Conditionalなら後続タスクを開始せず、設計と見積りを更新する。
- スパイクコードを製品へ残す場合は通常の設計・テストを経る。

## 4. 実装

### フェーズ着手条件

- 依存タスクとスパイクgateが完了している。
- 高リスクのリファクタリングでは先に契約テストがある。

### フェーズ完了条件

- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`
- `cargo test --workspace --all-features`
- UI変更時は`npm test`とVite build（D02前は現行`build-ui.ps1`）
- 要件IDに対応するテストまたは実機記録
- `git diff --check`
- impの実装報告更新
- 1フェーズ1コミット。コミットログは日本語

全workspaceテストを毎小変更で重複実行するかは、所要時間とリスクに応じて関連テスト→フェーズ末全量の順にする。

## 5. 検証

### 共通release gate

- CI全ジョブグリーン
- テスト戦略§5のSecurity gate全通過
- E2E smoke全通過
- 旧版DB/JSONからのmigrationとbackup復元
- Windows実機受入
- 既知P0/P1不具合なし
- README、ユーザーガイド、release notes同期
- version、artifact、SHA-256整合

性能は実測baselineからの重大退行がないことを確認する。100万件試験を全版の固定必須条件にしない。

## 7. 公開後

- GitHub Issue、Storeレビュー、利用者連絡を4週間確認する。
- 「報告がない」ことだけを品質証明にしない。
- 既知P0/P1、migration失敗、Security退行はhotfixを優先する。
- v1.0判定では4週間の運用記録と既知問題一覧を残す。

## 8. CI・ブランチ・供給網

- `main`はリリース済み、`feature/vX.Y.Z`は版開発。
- CIは最小`permissions`、外部Action full SHA固定。
- release/Store secretを通常PR CIへ渡さない。
- generated `ui/dist`はD02完了後Git管理せず、CI/リリースで生成する。

## 9. 版終了

- reqの完了条件を確認する。
- req/imp/必要なtaskを`dev/history/vX.Y.Z/`へ移す。
- 次版へ進む際は新しいreq/imp様式を生成する。
- 繰越は理由、優先度、依存をbacklogへ記録する。
