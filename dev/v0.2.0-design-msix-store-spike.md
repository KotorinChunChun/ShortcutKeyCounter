## 1. 前提

- 正式配布はMSIX + Microsoft Storeを目標とする。
- Store提出用MSIXに独自のCA trusted証明書を前提としない。Storeが認証後に署名する。
- Tauri 2はMSIXを直接bundleしないため、release exeと資産を`makeappx.exe`でpackageする。
- `runFullTrust`は必要だが、Store審査通過やLL hook動作を文書だけで保証しない。クリーンVMとWACKで実証する。

公式参照:

- [Microsoft StoreへのMSIX公開](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/publish-first-app)
- [Tauri Microsoft Store](https://v2.tauri.app/distribute/microsoft-store/)
- [MSIXデスクトップアプリの動作](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes)

## 2. 撤回する旧案

次は採用しない。

- `desktop6:FileSystemWriteVirtualization=disabled`
- `desktop6:RegistryWriteVirtualization=disabled`
- `unvirtualizedResources` Capability
- Store版とZIP版が同じ `%LOCALAPPDATA%\ShortcutKeyCounter` を直接使う前提
- アンインストール後もStore版データが自動的に残る前提

仮想化無効要素は制限付きCapabilityを必要とし、一般アプリの標準設計にできない。

公式参照:

- [FileSystemWriteVirtualization](https://learn.microsoft.com/en-us/uwp/schemas/appxpackage/uapmanifestschema/element-desktop6-filesystemwritevirtualization)
- [RegistryWriteVirtualization](https://learn.microsoft.com/en-us/uwp/schemas/appxpackage/uapmanifestschema/element-desktop6-registrywritevirtualization)

## 3. 技術スパイク（v0.2.0 M1）

期限を区切り、次を最小packageで実測する。

1. `makeappx`で自己署名dev MSIX生成
2. クリーンWindows 10/11 VMへinstall、起動、uninstall
3. WebView2がない/古い環境を含む起動方式
4. 通常権限アプリでLL keyboard/mouse hook
5. password欄Security Gate
6. StartupTaskからトレイのみ起動
7. package LocalStateへのSQLite/JSON保存
8. unpackagedデータからLocalStateへのコピー試作
9. WACK

各項目を`Pass / Fail / Conditional`で記録する。P0項目がFailならStore本実装を開始せず、manifest、配布方式、機能差を再設計する。

## 4. package identityとmanifest

Identityはdev/store JSONから注入する。store値がPartner Center未登録の間は生成を失敗させる。

manifestの最小骨格:

```xml
<Application
  Id="ShortcutKeyCounter"
  Executable="ShortcutKeyCounter.exe"
  EntryPoint="Windows.FullTrustApplication">
  <uap:VisualElements ... />
  <Extensions>
    <uap5:Extension
      Category="windows.startupTask"
      Executable="ShortcutKeyCounter.exe"
      EntryPoint="Windows.FullTrustApplication">
      <uap5:StartupTask
        TaskId="ShortcutKeyCounterStartup"
        Enabled="false"
        DisplayName="ShortcutKeyCounter" />
    </uap5:Extension>
  </Extensions>
</Application>
<Capabilities>
  <rescap:Capability Name="runFullTrust" />
</Capabilities>
```

実装時は対象MinVersionの最新schema例と`makeappx`検証結果に合わせる。StartupTask公式例: [StartupTask Class](https://learn.microsoft.com/en-us/uwp/api/windows.applicationmodel.startuptask)

## 5. データ保存と移行

### ZIP版

従来どおり `%LOCALAPPDATA%\ShortcutKeyCounter\` を使用する。

### Store版

package identityから取得したLocalStateを正本とする。固定文字列で`%LOCALAPPDATA%\Packages\<PFN>`を組み立てず、WindowsのApplicationData APIから取得する。

### 初回移行

```text
Store版初回起動
→ capture開始前にmigration状態確認
→ unpackaged data dirをread-onlyで検出
→ 対象ファイルとversionを検証
→ LocalState内にmigration backup作成
→ 一時ディレクトリへDB/JSONコピー
→ DB migration・整合性・Security sanitize
→ LocalStateの正規位置へ確定
→ migration marker保存
→ capture開始
```

要件:

- 元データを削除しない。
- 再実行しても重複・再加算しない。
- 途中失敗時はStore版を既定空データで黙って開始せず、復旧または利用者選択を求める。
- ZIP版とStore版を同時起動しないよう、移行後の案内とsingle-instance境界を設計する。
- package uninstallでLocalStateが削除され得るため、事前backup/exportをガイドする。

Microsoft公式もpackaged appのLocalFolderへの明示移行を推奨する: [unpackagedからStore packaged appへの移行](https://learn.microsoft.com/en-us/windows/apps/distribute-through-store/how-to-transition-users-from-your-web-unpackaged-app-to-store-packaged-app)

## 6. package判定

`GetCurrentPackageFullName`等の結果を3値で扱う。

- Packaged
- Unpackaged（`APPMODEL_ERROR_NO_PACKAGE`）
- Unknown/Error

UnknownをUnpackagedへ倒さない。storage初期化を停止し、captureを開始せず診断可能なエラーを表示する。

## 7. StartupTask

- packaged時はWinRT `StartupTask`、unpackaged時は既存HKCU Runを使う。
- `DisabledByUser` / `DisabledByPolicy`を区別し、アプリから強制的に戻さない。
- 起動理由を取得できない場合の「前回設定から推測」は採用前に誤起動条件をテストする。
- manifest extensionには`Executable`と`EntryPoint`を明示する。

## 8. Store版の機能差

昇格Capture helperはスパイクとStore方針確認が終わるまで同梱しない。Store版では機能を非表示または利用不可表示にし、通常権限とSecurity Gateは維持する。

ZIP版との機能差はStore本実装版のreqとユーザーガイドへ明記する。package判定不能時にhelperを起動しない。

## 9. WebView2

手動MSIXはTauri MSI/NSISのbootstrap処理を自動的には得ない。Windows 10/11の対象versionでWebView2 availabilityをクリーンVM実測し、必要ならStore/App Installerで許されるdependencyまたはfixed runtime方式を再設計する。

Tauri公式: [Windows Installer / WebView2 options](https://v2.tauri.app/distribute/windows-installer/)

## 10. build成果物

- `dev.msix`: dev Identity、自己署名、ローカル試験専用
- `store.msix`: Partner Center正式Identity、Store提出用。CA trusted署名を要求しない
- PFX、password、個人pathをGitへ入れない
- store Identityに`REPLACE_*`が残る場合はDB/資産をstageする前に失敗する
- buildは新規の空staging dirを使い、成果物manifestを記録する
