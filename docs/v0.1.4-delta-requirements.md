# ShortcutKeyCounter v0.1.4 差分要件

作成日: 2026-08-18

本書は `docs/v0.1.4-implementation-plan.md` の実装対象を、v0.1.3ユーザー修正版からの差分として要約したものです。詳細仕様は実装計画書を正とします。

## 1. セキュリティ不変条件

- 修飾なし単独keyboard/mouse/wheel入力は永続記録しない。
- 修飾なしMouseLeft/Right/Middle/X1/X2はOverlay表示のみ許可する。
- 修飾なしwheelおよびModifier-onlyはOverlayにも表示しない。
- Realtime Logへ流すのはDB記録対象イベントだけとする。
- Security GateはOverlay/DB/Realtime Logより前に実行し、判定失敗はFail Closedとする。
- Overlay退避クリックは修飾付きでもShortcutKeyCounter内部では完全破棄する。Windows側click-throughは維持する。
- キーマッピングの物理キー検索用1入力は検索結果にのみ使用し、Overlay/DB/Realtime Log/統計へ流さない。

## 2. 設定

- Overlay設定操作中の不要な再描画を抑止し、combo/selectの操作を中断しない。
- 固定モニター選択はdraft状態を許可し、複数モニター時は利用者が対象を選択してから保存する。
- Lightテーマの9位置選択状態を青背景・白文字にする。
- DuplicateGuardを0.0〜10.0秒、0.1秒刻みでruntime設定化する。0は無効。
- 詳細イベント保持を1〜365日で設定化する。
- 「設定保存後にサンプルを即時プレビュー」「現在の計測状態」を設定画面から削除する。

## 3. キーマッピング

- 表本体だけを独立スクロール領域とする。
- 分類フィルターと一括変更を上部横並びにする。
- 修飾列0件選択時はbackendを呼ばず「列を選択してください」と表示する。
- 次の物理キー1件を検索専用Captureで取得して該当行へスクロール・強調表示する。

## 4. 計測結果UI

左ナビゲーションの親見出しを「計測結果」とし、以下を配置する。

1. リアルタイムログ
2. ランキング
3. 使用率グラフ
4. キー × アプリ見取り図

ランキングはキー別とアプリ別を同一ページの左右2ペインへ統合する。

## 5. ランキング

- 期間: 今日 / 7日 / 30日 / 全期間。
- 今日の比較は「今日00:00〜現在時刻」と「前日00:00〜同時刻」。
- キー別ランキングは対象アプリfilterで再集計し、個数・平均・構成比・比較率・順位をすべて再計算する。
- 全期間平均はデータ存在日数を分母とし、アプリfilter時はfilter後のデータ存在日数を使う。
- アプリ別ランキングへ利用時間を表示する。
- 各列はクリックごとに「降順 → 昇順 → なし」の3状態sortとする。

## 6. 使用率グラフ

- モード: キーごと / アプリごと。
- 初期表示: ランキング1〜5位ON、6位以下OFF。
- 集計粒度: 今日=時間、7日=日、30日=日、全期間=月。
- 詳細イベント全件をfrontendへ送らずSQLiteでbucket集計する。
- 系列色は内部identity単位で永続化する。

## 7. Overlay連打圧縮

- DB DuplicateGuardとは完全に独立させる。
- 同一normalized identityの入力間隔700ms以内を同一runとする。
- 1回目は通常表示、2回目は2個表示、3回目以降は1トークンへ圧縮して `×N` を表示する。
- count更新時は数字部分だけ150〜250ms程度の専用animationを行う。
- 背景色、文字色、枠/影色、形状、回転角、フォントサイズを設定し、設定画面内PreviewとNative Overlayで同じschemaを使用する。

## 8. サンプルデータ

- Test DBだけへ生成する。Production DBへの直接生成はbackendでも拒否する。
- Production DBのapplicationと、Security invariant上記録可能なshortcut identityを母集団にする。
- 前日を最新日として過去60暦日、約10,000イベントを生成する。当日は生成しない。
- `shortcut_events` / `shortcut_daily` / `application_usage_daily` を整合させる。
- 前日分Realtime LogサンプルはTest DBへ生成済みの永続イベントからview-modelへ構成し、偽Captureを注入しない。

## 9. リリース

- Cargo/Tauri/README/成果物を0.1.4へ統一する。
- v0.1.3ユーザー修正版のbuild fixを維持する。
- WindowsでCargo build/check/clippy/test、Tauri package、Security/monitor/DPI/inputの実機受入を完了してからrelease-readyとする。
